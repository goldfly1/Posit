### QA Redesign Plan (commits 636166e, d0ff3d9, 119c9d5, 3a40c96)
Plan doc: `wiki/plans/qa-phase-redesign.md`

**Pipeline (redesigned):**
```
Build phase:
  C#Impl → 4 build retries → PASS or fail
  If build fails → WireFixer (2 retries) → PASS or hash (restart)

QA phase (Docker clean room):
  Pseudodata → Test runner → Judge (exact/invariant/heuristic) → Report
  FAIL (exact/invariant) → ImplFixer (2 retries) → PASS or hash (restart)
  FAIL (heuristic) → human review
```

**Key design decisions:**
1. Pseudodata bot — deterministic, reads carapace interfaces for type shapes + architect test case categories for data variety
2. Three-layer judge — exact match (computable transforms), invariant check (validator methods on carapace interface), heuristic check (one LLM call, anomaly detection only)
3. Fixers stay but capped at 2 each (was 6+3=9, now 2+2=4, total budget 8 was 13)
4. Docker clean room — QA lives inside Docker, reproducible environment
5. Restart on fail — pipeline is non-deterministic, restart is the exception handler
6. Human is tiebreaker on heuristic FAIL only (subjective call), not a debugger
7. Invariants on carapace — validator methods on the interface, model implements both, judge calls the validator
8. Structural fuzzy check replaces keyword rubber stamp (is output valid format? right fields? right structure?)

**Dogmatisms caught and fixed:**
- "No LLM call for pseudodata" → spec-aware deterministic bot, not just type-aware
- "Fuzzy matching removed entirely" → replaced with structural check, not removed
- "Fixers removed" → capped at 2, not removed (cheap fix is worth taking)

### Terminal Architecture
Four terminals on one carapace pipe:

| Terminal | Where | QA bot drives it? | Key-mapping? | Priority |
|----------|-------|-------------------|--------------|----------|
| CLI (pipe) | Data transformers, scripts | ✅ Yes (stdin/args) | No | ✅ Built |
| TUI (interactive terminal) | Docker QA, servers, SSH | ✅ Yes (keystrokes) | ✅ Yes | Next |
| GUI (desktop app) | End-user business software | ❌ Not in Docker | ✅ Yes | Later |
| AAI (AI assist interface) | Human conversational access | ❌ Non-deterministic | No | Later |

**Key-mapping convention** (for TUI and GUI):
- Ctrl+F1 = first page, focus on first field
- Tab = next field (standard accessibility)
- Every field has a known position in tab order
- Pages standardized — same layout conventions across all programs
- Purpose: QA bot always knows where fields are without discovery
- The convention serves the QA bot, not the human. The AAI serves the human.

**TUI is the QA terminal** — Docker has no display server. QA bot drives TUI with
deterministic keystrokes. No computer vision, no DOM inspection, no headless browser.

**AAI vision** — exec talks to computer ("show me overdue shipments"), AAI translates
to carapace method call (IShipmentTracker.GetOverdue()), renders result. Star Trek.
