### ContractScanner — root-cause fix
- **False positive on `for` in doc comments:** `iface.Contains("for ")` matched `for` as a preposition in XML doc comments ("override file1 for duplicate keys"). Fix: scan code lines only, skip comment lines (///, //, /*, *). Use regex `\bfor\b` word-boundary matching. **This was blocking T6/T11/T12** — the interfaces were clean, the scanner was wrong.
- **`format` added to IO-verb exclusion list:** "format" is frequently a noun in specs ("in the format [text](url)") not a verb, causing false spec-verb-coverage rejections (T11 blocked by this).

## Key Decisions
- **C# templates first, Dafny modularly second.** Templates handle 70% (structure: parse, validate, merge, count, sort, format). Model handles 30% (content: regex, arithmetic, branching). Dafny verifies templates for ALL inputs — proven correctness vs tested correctness.
- **Dafny as template language, not generation target.** Human writes Dafny template once, Z3 verifies once, compiles to C# (or Go, Python, Java — Dafny is multi-target). Model never writes Dafny.
- **WireFixer to be replaced by generator fixes.** WireFixer is a band-aid for deterministic generator bugs. Log compile errors, fix patterns in WiringGenerator, remove WireFixer when log goes empty.
- **Temperature discussion (pending):** Implementation should be 0.0 (translation), ImplFixer 0.1 (targeted fixes), WireFixer 0.0 (mechanical), QA 0.1. Architecture stays 0.3. Retry bump 0.7 doesn't help — drop it. Not yet committed.
