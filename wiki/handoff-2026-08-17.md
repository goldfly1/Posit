## Major Architecture Changes This Session

### 1. Model-Based Wiring (commit c35387f)
Replaced rule-based WiringGenerator with ModelWiringGenerator. The model sees connections,
method signatures, and type conversion table, then writes Wire.cs. Docker build verifies.
Falls back to rule-based if model fails. Fixes: JSON wrapper stripping, double-wrap prevention.

### 2. Hybrid Dafny Implementation (commit 7599c16)
DafnyImplementationPhase now has two paths:
- Cut-out components: skeleton exists → Z3 verify → translate (deterministic, no model)
- Custom components: no skeleton → model writes Dafny with reference card → Z3 verify → translate

### 3. Registry Eschewed (commit c159c16)
Cut-outs are now OPTIONAL, not required. The prompt says "WRITE YOUR OWN Dafny" with a
reference card. The model was picking wrong cut-outs and generic patterns. Now it writes
what it needs. Z3 is the judge. Cut-outs stay in registry for future use.

### 4. Auto-Harness (commit 108bc10)
`dotnet run -- run --spec="..."` now does everything: pipeline → Docker build → run tests →
compare output → LLM failure analysis. One command, full result.

## Known Issues for Next Session

1. **Model over-decomposes** when freed from registry — 6 components for a temperature converter.
   Needs prompt guidance: "2-3 components: one for I/O, one for logic. Don't over-decompose."

2. **Model-based wiring fragile** — sometimes returns JSON wrapper, sometimes double-wraps.
   Mostly fixed but needs retry loop for wiring errors (Docker build fails → retry with error).

3. **T3 branching** — scanner rejects unused WriteError on branching trials. Needs scanner
   to allow dead declarations for error-path methods when isValid branching is present.

4. **T5 multi-input** — linear chain can't express two-input merge. Model-based wiring
   should handle this (model writes the merge logic), but the architecture needs to
   not decompose it into separate read+merge components.

5. **QA test data JSON parse** — model returns wrong shape for TestDataFile[]. Need to
   handle the model's JSON format or make the prompt clearer.

6. **Registry eschewed** — model writes Dafny directly. Cut-outs optional. Need to verify
   this works for complex specs (T7-T12) where the model needs to write substantial Dafny.

7. **Retry limit** — MaxRetriesPerPhase=3 may be too low for complex specs. Consider 5.
