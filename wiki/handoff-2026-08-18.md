## What Changed (7 changes, 1 commit)

### 1. "Keep It Simple" Prompt (PromptBuilder.cs)
Added explicit anti-over-decomposition guidance to the architecture prompt:
- "Use 2-3 components: one io-shell for I/O, one or two dafny for logic. NEVER more than 4."
- "A temperature converter is ONE dafny component + ONE io-shell. Not six components."
- "Combine related logic into a single dafny component."
This directly addresses T6's failure (model decomposed temperature converter into 6 components).

### 2. Data Flow Spec Fields (ArchitectureContract.cs, DesignContext.cs)
Added two fields to Component:
- `EntryType`: "file" (args[0] as file path) or "stdin" (Console.ReadLine). Tells wiring how to read input.
- `BranchCondition`: e.g. "if !isValid: print error, exit 1". Tells wiring to emit an if-branch.
These are the missing richness in the connection format — the architect can now express
entry type and branching, not just method-to-method connections. Carried through
DesignContextSnowballer to DesignComponent.

### 3. Pre-Dafny TypeChainChecker (TypeChainChecker.cs, ArchitecturePhase.cs)
New method `CheckPreDafny()` runs AFTER architecture, BEFORE Dafny — the data flow spec
validation. Uses declared Dafny types (returnDafnyType, DafnyType) from the contract to
catch type mismatches before anyone writes code. Catches seq depth mismatches early
(e.g. string vs seq<seq<string>>). If the chain breaks, the error routes back to the
architect with actionable guidance ("use ReadLines for CSV, ReadFile for JSON").
The existing post-Dafny check (using scanned C# types) remains as a second gate.

### 4. ContractScanner T3 Fix (ContractScanner.cs)
When a component has branching (BranchCondition set or any method returns bool), error-path
methods (WriteError, PrintError, etc.) are allowed to be declared but unused in connections.
Previously the scanner rejected these as dead declarations, blocking T3.

### 5. Closed Correction Loops (FsmReducer.cs, PositOrchestrator.cs)
The `ForceRollback` flag on PhaseResult (which existed but was never used) is now wired
into `FsmReducer.ApplyPhaseFailed`. When a phase result has ForceRollback=true, the FSM
routes directly to `ApplyRollbackToArchitecture` instead of retrying the same phase or
aborting. Post-Dafny type chain failures set ForceRollback=true, so type mismatches now
route back to the architect with the correction signal.
EntryType and BranchCondition are passed to both wiring generators:
- WiringGenerator (rule-based): uses EntryType to emit Console.ReadLine vs args[0]
- ModelWiringGenerator: prompt includes entry type, branch condition, and "print VALUE not unit"

### 6. MaxRetriesPerPhase: 3 → 5 (Program.cs)
Complex specs need more retries, especially when the correction loop routes back to architecture.
