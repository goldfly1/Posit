## Session Arc

### 1. DafnyImplementationPhase Z3 Correction Loop
The DafnyImplementationPhase had no internal retry loop. Model wrote bad Dafny → Z3 rejected → FSM retried the whole phase from scratch → same mistake. Now has a 4-attempt correction loop (same pattern as DafnyFixer):

```
attempt 1: model output → Z3 rejects → feed previous Dafny + Z3 errors + HINT back
attempt 2: model sees its code + errors → targeted fix → Z3 rejects or accepts
attempt 3-4: continue until Z3 verifies or exhausts
```

### 2. "Not Dafny" Error Detection
When Z3 says "this symbol not expected in Dafny", the correction prompt explicitly tells the model:
"⚠️ CRITICAL: Your previous output was NOT valid Dafny code! Output ONLY raw Dafny source code."
Catches the common failure where the model wraps Dafny in JSON.

### 3. Z3Runner --verbose + Opaque Error Translation Layer
Dafny's CoCo parser produces opaque "invalid UnaryExpression" / "rbracket expected" / "this symbol not expected" errors with no explanation. Web research confirmed this is a known, systemic problem (GitHub issues #4606, #5047, #6180) — the CoCo/R parser generator has no better message. Dafny 5.0 proposes a fix but no timeline.

Added `--verbose` flag to Z3Runner verify command (zero downside — normal errors unchanged). Built `TranslateOpaqueErrors` layer that:
- Detects `p_generic_syntax_error` and related opaque parser messages
- Reads the Dafny source at the error line
- Inspects surrounding context (is the error inside a `function` or `method`?)
- Appends a plain-English HINT the model can act on

Hint patterns implemented:
- `while`/`var`/`return` inside `function` → "change function to method or rewrite as recursion"
- `rbracket expected` near `map[` → "use `map[K, V]` with comma, not `map[K]V`"
- `rbracket expected` near `seq[` → "use `seq<T>` with angle brackets, not `seq[T]`"
- JSON output (`{"`) → "output raw Dafny starting with 'module'"
- `while` without invariant → "add invariant and decreases clauses"
- Generic fallback for unknown opaque errors

Proven on T8: map syntax hint fixed between attempts 1→2. while-in-function hint correctly identified the issue.

### 4. Pseudocode Crystallization Fix
`IsCrystallized` was vacuously true on pass 0 — the raw spec (signature + responsibility + test lines) had all lines filtered out, leaving zero substantive lines, and returned `true`. Fix: require at least one substantive line.

Also: accept STOP variants (case-insensitive, StartsWith, short output containing "stop") and very short non-STOP output (< 5 chars — model gave up) as crystallized. The model knows better than the heuristic whether the pseudocode is reduced enough.

### 5. DafnyImpl Prompt: Ban `function` + Reframe as Refactor
**The breakthrough that got T12 green.** Two prompt changes:

1. **BAN `function`**: Rule 4 now says "ALWAYS use `method`, NEVER use `function`. Functions are pure expressions (no loops, no mutable assignment). Methods allow imperative code." This eliminates the entire `invalid UnaryExpression` class of errors — the #1 Dafny parse error across all trials (GitHub issue #5047).

2. **REFACTOR framing**: "You are refactoring reduced pseudocode into valid Dafny. The pseudocode IS the algorithm. Do NOT redesign it. Your job: wrap it in method signatures, add contracts, fix syntax to valid Dafny. That's all."

### 6. Broadened JSON Dafny Extraction
The JSON scanner was only looking for `"method "` or `"module "`. Now also detects `"var "`, `":="`, `"if "`, `"return "`, `"requires "`, `"ensures "`, `"function "`, `"datatype "` — catches Dafny code fragments wrapped in JSON body fields.

## Model Routing Findings

- **deepseek-v4-flash:cloud**: Good for architecture + pseudocode reduction. Gets through those phases fast (1-2s per call). Gets stuck on Dafny type errors but the correction loop + error hints help it recover.
- **deepseek-v4-pro:cloud**: Good for Dafny writing (reasons better through type relationships). But fails at pseudocode reduction (outputs 14 tokens = STOP on every pass, never crystallizes). Also slower (22s for architecture vs flash's 5s).

- **Per-phase model routing** is the answer: flash for architecture + pseudocode, pro (or flash with hints) for Dafny. Session resume (`posit resume <sessionId>`) allows swapping models between phases.
