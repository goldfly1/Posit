## Carapace Enforcement

Two deterministic gates now exist:

### 1. Must-have list (Architecture phase)

Enforced by `ArchitecturePhase.ValidateOutputAsync`:

- `systemContext` is non-empty.
- At least one component exists.
- Every component has non-empty `id`, `name`, `responsibility`.
- Every component has at least one test case.
- Component `name`s are unique and do not end in implementation noise (`.Implementation`, `.Implementations`, `.extern`, etc.).
- `classification` is exactly `dafny`, `io-shell`, or `mixed`.
- `dafny`/`mixed` components declare a `patternName`.
- `io-shell` components declare a `tech`.
- Web / ASP.NET / HTTP `io-shell` components list `Program` in `publicSurface`.
- Dependencies resolve to other components; no cycles (validated by corrected DFS).
- `dataStores`, `interfaces`, `qualityAttributes`, `decisions` are present.

### 2. Not-a-thing list (C# Implementation phase)

Enforced by `PositOrchestrator.ValidateCSharpCarapace` after phase success:

- Every generated file path must start with an authorized component directory from the architecture contract.
- Invented directories (e.g., `MigrationRunner`) are rejected with `carapace.off_list.directory`.
- `Shared/` is allowed as a common utilities directory.

## Carapace Principles (still in force)

1. The `.dfy` skeleton is the contract.
2. Patterns are objects cut from whole cloth, not partial classes to fill later.
3. Imp only inlays function into pre-cut `{:extern}` portals.
4. If a phase makes up names, the fix is contract enforcement, not more tolerant parsing.
5. **New:** The shell is tattooed with the entry point; Imp may not move it.
6. **New:** The architecture contract is the authoritative directory list; Imp may not add directories.
7. **New:** The verifier is the build judge; a model's “completed” claim is not a pass.
