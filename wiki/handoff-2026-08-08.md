Final Docker error after systemic verifier improvements:

```
Skipping project "/src/MigrationRunner/MigrationRunner.csproj" because it was not found.
error MSB4006: There is a circular dependency in the target dependency graph
  involving target "_GenerateRestoreProjectPathWalk".
  [/src/TodoRepositoryLogic/TodoRepositoryLogic.csproj]
```

Remaining root causes:

1. **Wrong project file name assumption.** The verifier assumes each project directory contains `{dirName}.csproj`. T3's C# Implementation phase put the API inside a directory named `MigrationRunner` but named the project file `TodoApi.csproj`. The inferred `ProjectReference` then points to a non-existent `MigrationRunner.csproj`.
2. **Circular project references.** The type-name heuristic inferred a bidirectional reference between `TodoValidator` and `TodoRepositoryLogic`.
3. **Structural misplacement.** The API, migrations, integration test factory, and repository I/O shell were all emitted into the `MigrationRunner` module instead of being separated into `TodoApi`, `TodoRepositoryDb`, etc.

These are model-output structural issues, not per-dependency band-aids. The verifier can be made more defensive, but the clean fix is in the C# Implementation / architecture prompts: enforce one module per bounded context and forbid nested projects with mismatched directory/file names.
